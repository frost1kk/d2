# LOGIC — логика и алгоритмы бота

## Единая модель состояний (`src/main.py`)

Клавиши: движение — **A/D**, пуск/подтверждение — **пробел** (с удержанием KEY_TAP_HOLD_S,
т.к. мгновенный тап игра не ловит). Один механизм проходит старт, пред-пуск, потерю мяча и
переходы между уровнями — без отдельных «фаз пуска».

Ключ — различение **летит vs висит** по вертикальному ходу сапога за окно FLIGHT_WINDOW:
в полёте y активно меняется; в прицеле/пред-пуске y почти постоянна (двигается только x).

```
PLAY — сапог виден и ЛЕТИТ (разброс y за окно > FLIGHT_Y_RANGE_PX):
       ловим — tracker.update, цель=select_target, A/D к цели (follow-x).
AIM  — сапог виден, но ВИСИТ (разброс y мал = пред-пуск/прицел):
       тележку не двигаем (не сбивать прицел), жмём пробел (запуск) с кулдауном.
MISS — сапога нет < BALL_LOST_FRAMES кадров (нырнул к тележке): держим, окно НЕ чистим,
       чтобы полёт продолжил ловиться сразу после появления сапога.
LOST — сапога нет ≥ BALL_LOST_FRAMES (меню/переход между уровнями): чистим окно,
       жмём пробел (проходим экран/запускаем следующий уровень) с кулдауном.

пробел — не чаще LAUNCH_COOLDOWN_S (без спама). При --manual пробел не жмётся вовсе.
```

**Почему так.** Ранний вариант «есть сапог → ловим» застревал на 2-м уровне: после экрана
перехода сапог висит в пред-пуске (напр. 960×384, y≈const), а бот принимал его за летящий и
гонял тележку, не запуская. Различение по вертикальному ходу решает это единообразно для всех
уровней. Проверено на логе перехода (`--log`): переход и пред-пуск ур.2 распознаются, ловля
ур.1 сохранена, ложных нажатий пробела в полёте ~1/уровень.

> ⚠️ **Пауза при потере фокуса.** Игра встаёт на паузу, когда её окно не активно. Для боя это
> НЕ проблема: цикл захватывает экран из фонового процесса, а ввод (SendInput) уходит в
> активное окно — игра должна оставаться в фокусе, терминал фокус не забирает. Проблема лишь
> при ручном снятии кадров из терминала — для этого в `capture.py` есть `--delay` (успеть
> кликнуть по игре до захвата).

## Предсказание точки падения (`src/track.py`)

Система координат экранная: x вправо, **y вниз**. Сапог, падающий к платформе, имеет `vy > 0`.

### Скорость
Берётся как разница двух последних позиций сапога (пиксели/кадр). Реальное время не нужно:
точка падения зависит только от наклона `vx/vy` (время сокращается в `x + vx·t`, `t=(yp−y)/vy`).

### Формула точки падения
```
t      = (y_platform − y) / vy          # только при vy > 0
x_raw  = x + vx · t                      # без учёта стенок
x_land = reflect_1d(x_raw, x_left, x_right)
```

### Отскоки от стенок — `reflect_1d` («треугольная волна»)
Многократные отражения от левой/правой стенок разворачиваются в одну формулу:
```
width = hi − lo
p     = (value − lo) mod (2·width)
если p > width:  p = 2·width − p
результат = lo + p
```
Примеры (для [0,100]): `130 → 70` (один отскок), `310 → 90` (несколько), `−30 → 30`.

### Когда предсказания нет (`None`)
- `vy ≤ 0` — сапог летит вверх/горизонтально, к платформе пока не идёт.
- `y ≥ y_platform` — уже на/ниже линии платформы.
- Нет двух позиций подряд — скорость ещё не определена.

## Стратегия и управление (`src/control.py`)

**Выбор цели (`select_target`, двухрежимный):**
```
сапог не виден            → None (держим позицию)
сапог ниже линии блоков и падает и предсказание в пределах max_shift → точка падения
иначе                     → x сапога (следуем)
```

**Стратегия v1 = follow-x.** Предсказание точки падения (`predict_landing_x`) выключено
(`config.USE_LANDING_PREDICTION=False`). Причина — из данных реального спуска (400 кадров):
траектория к тележке почти вертикальна (x держится ~930–975), а vx шумный; экстраполяция
через ~250 px по вертикали раздувала шум в ошибки ±100 px (прицел скакал 800…1240). Follow-x
попадает в реальную точку точнее. Предсказание оставлено для будущих угловых бросков с
устойчивой оценкой скорости (регрессия по N кадрам). Скорость сглаживается EMA
(`VELOCITY_SMOOTHING`).

**Направление (`decide_direction`):**
```
если цель_x is None:            → STAY (не дёргаем платформу вслепую)
delta = цель_x − тележка.x
если |delta| ≤ deadzone:        → STAY   (гистерезис против дрожания)
иначе:                          → RIGHT(D) если delta>0, иначе LEFT(A)
```

## Детекция (`src/detect.py`)

Захват — **весь рабочий стол 1920×1080**; мини-игра — модальная панель по центру. Геометрия
поля задана абсолютными пикселями (`config.FIELD_*_PX`), измеренными по реальному кадру, и
масштабируется под фактический размер кадра.

- **Поле** — прямоугольник x∈[655,1272], y∈[155,965] (при 1920×1080). Границы — золотые
  колонны (x≈640/1278) и нижний край HUD (y≈155).
- **Тележка** — центроид бирюзового «стекла» тележки в нижней полосе (y≳850): симметрично,
  даёт ~центр тележки (≈960). Резерв — красный баннер (смещён эмблемой на ~+30 px).
- **Сапог** — крупнейший блоб бирюзовой HSV-маски (свечение сапога, H≈85–105) в поле **выше**
  полосы тележки. Полоса важна: «стекло» тележки — та же бирюза, поэтому сапог ищем только над ней.

Подтверждено на опорных кадрах: сапог (934,620), тележка (988,887); синие гемы UI Dota вне
поля не мешают. Тесты — `tests/test_detect.py`. На серии из 200 кадров полёта сапог
детектируется на **100%** без пропусков (площадь блоба 21..90, порог 12).

**Физика (из записи):** сапог **рикошетит среди блоков** вверху поля — траектория не
парабола, направление меняется каждые несколько кадров при ударах о кирпичи. Поэтому
`predict_landing_x` даёт надёжный прицел только на **финальном спуске** в открытой нижней
зоне (ниже блоков); пока сапог наверху — предсказание шумит (стратегия управления — M2).

> ⚠️ Остаточные риски (BACKLOG): (1) центр тележки по красному смещён на ~30 px — уточнить;
> (2) сапог мелкий (площадь ~60 px), на части кадров свечение может слабеть — для live
> предусмотреть frame-differencing (движется только сапог) или template-matching как fallback.

## Edge-кейсы и устойчивость

- **Промах детекции сапога** (None) — трекер сохраняет прежнюю скорость, цикл не рвётся.
- **Кадр None от dxcam** — пропускаем итерацию (grab между кадрами).
- **Тележка не найдена** — ввод не подаётся в этот тик (нет опорной точки).
- **Выход из цикла в любом случае** — `finally` отпускает клавиши (нет «залипших» стрелок).

# Changelog

Все значимые изменения проекта. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Unreleased]

### Fixed (по live-фидбэку)
- 🚀 **Стартовая секвенция исправлена** под реальную механику: **пробел (подтвердить старт)
  → пауза → пробел (запуск)**. Убраны ошибочные центровка тележки и «фаза позиции» перед
  первым пробелом (её выбирать не нужно). Направление — по умолчанию.
- ⌨️ **Нажатия пробела с удержанием** (`KEY_TAP_HOLD_S`, ~80 мс) — мгновенный keyDown/keyUp
  игра на Source 2 часто не считывала (причина «немого» автопуска).
- 🧪 Режим `--test-launch` — прогнать только секвенцию пуска и выйти (подбор пауз вживую).
- Подтверждено: предсказание точки падения на низких высотах некорректно → остаётся
  выключенным (follow-x), см. `USE_LANDING_PREDICTION`.

### Added (готовый к работе продукт)
- 🎮 **Конечный автомат `src/main.py`** со стартовой секвенцией мини-игры: SETUP
  (центровка тележки A/D → пробел → направление → пробел → пуск) → PLAYING (ловля). При
  потере сапога — возврат в SETUP и авто-перезапуск. CLI: `--manual`, `--delay`.
- ⌨️ **Управление A/D** (не стрелки) + пробел для пуска/подтверждения (`config.KEY_*`).
- 🎯 **Двухрежимная стратегия `control.select_target`** + сглаживание скорости EMA
  (`BootTracker.smoothing`). **v1 = follow-x**: предсказание точки падения выключено
  (`USE_LANDING_PREDICTION=False`) — по данным реального спуска оно шумит (экстраполяция
  через ~250 px раздувает шум vx в ошибки ±100 px), follow-x точнее. Предсказание оставлено
  для будущих угловых бросков.
- 📊 Периодический замер latency/FPS цикла в `main`.
- ✅ Тесты стратегии и свойств трекера (`select_target` ×6, `vy/last` ×1). Итого 38 зелёных.

### Changed
- 🛒 **Центр тележки — по бирюзовому «стеклу»** (центроид всей маски ≈960, истинный центр),
  вместо красного баннера (смещён эмблемой на ~+30 px). Красный — резерв.

### Changed (детекция)
- 🎯 **Детекция откалибрована по реальному захвату** (два опорных кадра 1920×1080):
  - Захват оказался **полным рабочим столом**, а мини-игра — модальная панель по центру.
    Геометрия поля переведена с долей кадра на **абсолютные пиксели** (`config.FIELD_*_PX`,
    масштабируются под кадр): колонны x≈640/1278 → поле x∈[655,1272], верх y≈155.
  - Детекция **поля/тележки/сапога подтверждена на живых кадрах**: сапог — бирюзовый блик
    (934,620); тележка — красный баннер (~988,887); синие гемы UI Dota больше не ловятся
    (поиск ограничен полем). Пороги сняты из реальных пикселей (`debug/inspect_frame.py`).
  - Линия ловли сапога берётся из `cart.y` каждый кадр (а не низ поля).
- `capture.py`: флаг `--delay` — пауза перед захватом, чтобы вернуть фокус игре (игра встаёт
  на паузу без фокуса окна) и поймать живой кадр.

### Added
- ✅ Регрессионные тесты детекции на реальных кадрах (`tests/test_detect.py`, 5 тестов):
  границы поля, позиции сапога/тележки с допуском, `boot=None` в пред-запуске.
- `debug/inspect_frame.py` — инспекция HSV реальных ROI + вырезка патчей для калибровки.
- `capture.py --record N` — серийная запись кадров (видео-режим dxcam); `debug/detect_series.py`
  (сводка устойчивости) и `debug/plot_trajectory.py` (визуализация пути сапога).
- ✅ **Детекция сапога подтверждена на серии из 200 кадров полёта: 100%**, без пропусков
  (площадь блоба 21..90). Порог `MIN_BOOT_AREA` снижен 20→12 для запаса. Выявлено: сапог
  рикошетит среди блоков (не парабола) → дальнее предсказание точки падения осмысленно лишь
  на финальном спуске в открытой нижней зоне.

### Added (скелет)
- 🎯 **Скелет бота** для мини-игры «Сапожный снос»:
  - `src/config.py` — пороги детекции (HSV), геометрия поля (ROI-соотношения), клавиши,
    мёртвая зона, бюджет цикла. Значения детекции — первый прикид с опорных кадров.
  - `src/track.py` — предсказание точки падения сапога с отскоками (`reflect_1d`,
    `predict_landing_x`, `BootTracker`). Чистая математика, без OpenCV.
  - `src/control.py` — управляющая логика с гистерезисом (`decide_direction`, `Controller`).
  - `src/detect.py` — детекция поля/тележки/сапога (OpenCV, HSV-маски) + отладочная разметка.
  - `src/capture.py` — захват через dxcam + CLI `--save` для опорных кадров.
  - `src/input.py` — эмуляция ввода (pydirectinput, удержание стрелок, гарантированный release).
  - `src/main.py` — управляющий цикл + kill-switch (F12 / Ctrl+C).
  - `debug/overlay_frame.py` — оффлайн-проверка детекции на сохранённом кадре.
- ✅ **Юнит-тесты** чистой логики (`tests/test_track.py`, `tests/test_control.py`) — 26 тестов,
  все зелёные. Покрывают отскоки, предсказание, трекер, управление, edge-кейсы.
- 📄 Документация: `README.md`, `LOGIC.md`, `ARCHITECTURE.md`, `BACKLOG.md`, `ROADMAP.md`.
- 🔧 `requirements.txt`.

### Примечание
- Модули `detect`/`capture`/`input`/`main` написаны, но **ещё не валидированы** на реальных
  кадрах / вживую. HSV-пороги детекции требуют настройки — см. [BACKLOG.md](BACKLOG.md).
